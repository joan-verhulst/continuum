# Patterns

A common need, and the parts it is built from and how they sit. Each row starts, in bold, with **when** the
recipe is the answer, and says where a simpler thing does the job instead; then the simpler thing wins. A
recipe answers a need the content has: none is added because a page of that kind usually shows one. Each row
names the parts (`components.md`), the placement (`pages.md`) and the values that matter; the medium files say
how to write them. Where a need is not here, build it by the recipe in `method.md` from the nearest row.

| Need                       | When, and build it as                                                                                         |
| -------------------------- | ------------------------------------------------------------------------------------------------------------- |
| **List of objects**        | **When many things of one kind are looked through and opened**: a ruled table in its frame: head 41 on the `neutral-100` fill, rows 41 with a hairline between, 12 padding; the first column the name (13 medium `neutral-900`), meta columns `neutral-700`, numbers tabular right, status a badge, people a 24 avatar and name, the last column (44) a ghost ellipsis for the row's menu when a row has actions of its own. Group rows (34, muted, full width) only when the list falls into sections. A row opens the object's own page. Key–value facts are label and value rows and settings a settings list, not a table. |
| **Views of a list**        | **When the same list is cut into a few standing sets the reader moves between**: status views (All · Drafts · Published) with their counts in the dock at the panel's foot, beside the dock action for the page's primary. A list with one view has no dock; an attribute to narrow by is a filter; how the list is shown (List · Grid) is a view switch. |
| **Filters**                | **When a list is too long to read whole**, one filter per attribute the reader narrows by and none for the rest. Row 1, the toolbar, never moving, as the table's own top bar inside its frame (`TableToolbar`): search (34, 256 wide), always, unless the items have nothing to type, then a segmented control for one-of-few that should stay visible, a 34 select per value for the one or two always at hand, or a Filter button (secondary, a filter icon, a count once applied) for several groups of values, opening grouped checkbox values with "Clear all" at its foot. Row 2, only when filters apply, under it, still inside the frame: a soft chip per group (24 high, pill, the `neutral-100` fill, no border, 13 `neutral-600`, a 12 × at the end: "Status is Paid or Overdue"), wrapping, then a ghost "Clear all". A table whose filtering is the work takes filter conditions (`components.md`). |
| **Selection of rows**      | **Only when rows can be acted on together** (a selection needs its bulk actions): a checkbox column (20 boxes; the head's box mixed when some are selected); selected rows on the 7% wash; a floating toolbar (38, `control` corners) at the foot with the count and the bulk actions, taking the dock's place while anything is selected. |
| **Inline add**             | **When lines are added to a table in place, one after another** (an invoice's lines): a last table row holding a ghost button with a plus ("Add line"), its padding pulled so the label aligns with the first column's text. An object with a page of its own is added by the page's primary action instead. |
| **Totals under lines**     | **When a table's amounts add up to sums the reader needs** (an invoice, an order): a footer in the same table, each sum in the column of the amounts it totals: a slim head row (the `neutral-100` fill, 8 vertical padding) naming those columns, then a row per sum on the surface with no rules between (the label in `neutral-700`, 16 in from the edge), the total last with a hairline above it and 12 / 16 padding. |
| **Editable cells**         | **When the table is where its values are worked on** (an invoice's lines); a list whose rows open their own page is edited there, not in place. The table reads as values; a cell becomes editable on click: the value in a borderless 13 input on the tint wash, the text where it was, a select for a value from a set (a VAT rate: the value and a small chevron, its list under the cell). Under the pointer or on focus an editable cell shows a 14 mark at its end, a pencil for a typed value and a chevron for a pick: the one hint it can change, with the pointer cursor (a click starts the edit). The open cell is ringed inside its edges in the accent (2) and ends in a 20 check that saves; Enter or a click away saves too, Escape puts the value back, and focus returns to the cell; a figure that does not read as one is not taken. Only the values the reader sets are editable: a sum the table works out (an amount, a total) stays a plain cell and follows the edit. The row keeps its height. |
| **Status / workflow**      | **When an object is in one of a few named states**: a soft badge (`components.md`) in the tone of what the state is (`foundations.md`, Status colour). Never a coloured row. |
| **Key figures (KPIs)**     | **When the reader needs several figures at a glance**, two to four, first under the head (before a chart): stat cards (`components.md`) in a row, 16 apart, each holding the same lines (a label, a value and the same kind of line under it), so the row ends level. One figure is a line of text or the head of its chart card, not a card; a fact that happens to be a number goes with the facts. |
| **A chart**                | **When the shape is what the reader needs** (a measure over time, a comparison, shares of a whole), not one figure: the chart for the need, by the table at the head of `charts.md`, in its card. One figure and its change is a stat card; a ranked list of names is a bar list. |
| **Ranked breakdown**       | **When the reader's next question is "from where", and the names are the point** (top pages, sources, countries): a bar list, its anatomy as in `components.md`, its bars neutral; it collapses to "Show N more" when it runs long; rows are filter toggles only when picking one narrows the page. A comparison across categories is a chart. |
| **Key–value facts**        | **When an object has attributes to look up**: label and value rows, the label at the left, the value beside it (a DescriptionList in the column; in the side panel the same rows without its box), several groups of facts as titled groups of one list, never a card each built alike. A grid of label-over-value pairs only for two or three headline facts in a tight spot (a sheet's head). Icon-led facts (location, device) as a wrapping row of 16 icons with text. A read-only value the reader copies (an ID, an API key) as a value field with a copy action. |
| **A list that can grow, on a page about something else** | **When a section of a detail or an overview lists items that can run to dozens or hundreds** (an account's deals, a project's tasks, a customer's invoices): the section shows the latest or most urgent few, about 10, its count in the head ("Deals 140"), and a ghost "View all" at its right opening the whole list where it can be searched and paged: the object's own facet (a tab or a view in the dock) when it is one of the object's views, otherwise a sheet. |
| **Timeline / history**     | **When the reader asks what happened to an object**: an activity list in a sheet, read beside the page, its anatomy as in `components.md`: an icon tile per item, the title over its time. The latest few may close a detail page, with "Full history" opening the sheet. |
| **Steps of a run / a log** | **When a run is read step by step, each with its result and duration**: a bordered list (card corners) of rows 41 or more, divided by hairlines, each with the same lanes left to right: a step number (13 `neutral-600`, 24 wide), an icon tile (32), the text (what happened, 13 medium, with the tool or object as a mono chip, and one line of result in `neutral-600`), the duration right in `neutral-600`, a badge only when the step is exceptional (retried, approved, failed), a chevron to open it. An open row takes the 3% wash and shows its detail below the text: attempts as a small list with times, input and output as code blocks (11 mono on the `neutral-100` fill, chip corners, 12 padding), side by side at 896. Normal steps carry no badge. |
| **Schedule / planner grid** | **When work is planned per resource and per day**: a bordered grid (card corners): the first column the resource (name 13 medium over a meta line, 56 rows when two lines), then a column per day with the day as a 41 head on the `neutral-100` fill, today's column on the 3% wash; hairlines between rows and columns (the one grid that divides both ways). Items in a cell are small blocks (item corners, the surface, a hairline, 8 padding): a 6 status dot, the task 13 medium, the time and person 11 `neutral-600`. A footer row of meters only when the resources have a capacity to fill. |
| **Empty state**            | **Where a list or section has nothing yet**, in its place: a left-aligned dashed panel (`panel` corners, 20; a dashed hairline): an optional icon tile, what goes here (13 medium), one sentence (13 `neutral-600`), one secondary button. No illustrations. A filter that matched nothing offers to clear it. |
| **Loading**                | **While content loads**: skeleton blocks and lines at the real element's size, the region marked busy. No spinner over a page; a spinner only inside the button that is busy. |
| **Search**                 | **When the reader looks things up by name**: a small input (34) with a leading search icon, level with the buttons beside it; a trailing kbd (⌘K) only when that shortcut opens it. |
| **Command palette**        | **When the product offers search-and-run from the keyboard** (⌘K): a dialog pinned near the top with a borderless search, groups of 36 rows that hide when they do not match, the recent records first, then places, then actions, each with its kbd or a quiet hint. The search of one list is the search input on that list. |
| **Create or edit**         | **When one object is made or changed**: the create or edit page kind: fields stacked at 640, sections 40 apart when the fields fall into groups, the primary at the end. A short form (two or three fields) is a 480 dialog instead. |
| **Long form / wizard**     | **Only when the form is long**: a stepper over the form (horizontal above, or vertical beside a long one), the current step's fields under it, Back and Continue at the end; done steps can be returned to; a step with errors is marked and says what is missing. A form that fits one page of sections has no stepper. |
| **Settings**               | **For the standing choices of a product or an account**: the settings page kind: one card per group, rows divided by hairlines, one switch or picker per setting, a dependent setting sharing its parent's space between hairlines (or under an eyebrow), the areas in the dock when there is more than one. One object's own properties are a facet of that object (below). |
| **Choice with explanation** | **When each option needs a sentence to be chosen well** (a plan, a mode, a permission): an option list: rows with a label over a description and a radio or checkbox in the trailing slot, 16 apart, each a hairline row when there are more than three. Options that are clear from their labels are plain radios, or a select from five up. |
| **A single toggle with consequences** | A setting row with a switch, its description saying what turns on; a confirmation dialog only when it cannot be undone. |
| **Save state**             | **When changes save as they are made**: a notice in the header bar: "Saving…" with a small spinner, then "Saved", sliding out from under the bar and leaving by itself. The same for small actions without undo ("Link copied"). |
| **Feedback after an action** | **After an action, with Undo for anything reversible**: a toast (`components.md`). A small action with nothing to undo gets a notice instead (Save state). A message that must stay is an alert in the page (a bordered row with an icon, 13, in the status tone). |
| **Destructive action**     | **When an action removes something for good**: last in the row's menu, in `error-600`; confirmed in a dialog whose primary is labelled with the verb ("Delete page"). One that can be undone asks nothing first and offers Undo in a toast after. |
| **Explaining a heading**   | **Only when a title needs explaining**: an info tip (a 16 icon that opens a short popover) beside the title; never a paragraph of help text under it. |
| **Onboarding**             | **While a new workspace has set-up steps left**: a checklist card on the overview: the count and a bar, done steps ticked, the next one open with its action and a ghost Skip. |
| **An object's properties** | **When an object has settings of its own**: a facet of its own: the Settings view in the object's dock or tabs, its fields stacked at 640. |
| **The people or things that belong to an object: members, a team, services** | **When the reader needs who or what belongs to an object, and how each stands** (a project's members, a release's services, an order's shipments): a list card titled with the count (the count 13 `neutral-600` after the title), rows 12 apart, each row one line of lanes: a 24 avatar for a person or a 16 icon in `neutral-600` for a thing, 12 to the name 13 medium `neutral-950` over one line of what it is 13 `neutral-600` (2 between), and at the right how it stands now, as a badge or a status dot with the word. When states differ, the one that needs the eye first. |
| **Live state**             | **Only when the thing is live now** (people online, a sync running): a status dot (pulsing when live) beside the thing it describes, in that thing's card and not the page head; a live count as a figure with a dot ("129 Active now"). |
| **A value against its range** | **When a reading is judged by the range it should sit in** (a test result, a temperature, a stock level, a response time): the range drawn as a band on a track with the reading's place marked on it, the band in the success wash, the reading status-coloured only when it is outside; the value right-aligned beside the track with its unit, its change since the last reading after it as a delta. Several readings start with how many are outside, and the outside ones lead. A target and graded ranges rather than one band: BulletChart (`charts.md`). |
| **Usage / credits**        | **When an amount is used out of a known allowance**: a meter with a label and a caption ("4 of 5", "Resets in 10 days"); progress only for a task that finishes. A tone only when the amount warrants it (near the limit `warning`, over it `error`). |
| **Date / date range**      | A date picker in a form (38, a calendar icon); a date-range picker with its presets (Last 7 days, Last 90 days) for filtering a report or overview, when the reader can change the period; a calendar inline only when the month itself is the content. |
| **Sign-in code**           | **When signing in asks for a one-time code**: a code input (large when it is the page's only task), a resend ghost button, the error in the field's helper line. |
| **Drop zone / upload**     | **When the reader adds files**: a dashed well (item corners) with a line on what goes here and a secondary "Choose files"; on drag-over the dash darkens and the 3% wash fills it; the files follow as rows with a bar while uploading. |
| **Media grid**             | **When things are told apart by how they look** (images, files with a preview); things told apart by name are a table. Tiles four across, 12 apart: item corners, a hairline, a 4:3 thumbnail on the 4% wash, then the name 13 medium and the meta 11 `neutral-600` in 10 padding. Selected: the 2px action outline, 2 outside. |
| **Board / kanban**         | **When things move through a few stages and are moved by hand**; a status that is only read is a badge in a table. Columns on the `neutral-100` fill (card corners, 8 padding, 8 between cards) with a header (title and count badge); cards the surface with item corners, a hairline, 12 padding; the `float` shadow only while dragging. |
| **Document / rich text**   | **When the content is writing**: no box around it: the text sits on the panel at 14–16 with relaxed leading in `neutral-900`, 680 wide; headings medium at 24 / 18 / 16; a floating toolbar over the selection; blocks get a ghost grip handle on hover in the left margin. |
| **Chat / support: a thread, who is typing, attaching a file, a failed or unread message, a reference by #** | **When people talk in turns** (support, comments); a history is an activity list and a run a log. A thread of messages with the composer at its foot, by the chat parts in `components.md`: the thread (its loading, unread and jump-to-latest states are its own), the message (own and others', pending and failed), the typing row in the composer's slot, the composer with what is attached waiting above its box, and a record or person referenced by "#" or "@" as a neutral token. |
| **Ask an AI / an agent page** | **When the product has an assistant the reader asks**: the assistant page kind (`pages.md`), its prompt and thread by the chat parts in `components.md`; the recent chats under the empty prompt as rows of 32, title left, age right in `neutral-600`, a primary dot when unread, no rules. |
| **Tree / hierarchy**       | **When places nest** (a collection and its pages): nav groups with inset items; each deeper level indents another 32. A place with a long index of its own drills down into a level instead. |
| **Workspace / project switch** | **Only when the product has several workspaces or projects**: a sidebar switcher under the sidebar's header (or the footer account made one): the current one's 28 mark, name over a quiet line, a menu of the others with a check on the current, then "All …" and "New …". A breadcrumb menu only for siblings deeper in the trail. With one workspace, the footer account names it. |
| **View switch**            | **When the same content can be shown more than one way** (List · Grid, Draft · Preview): a segmented control (34 track, 29 items); tabs only for the facets of one object on its detail page. |
| **A page on a phone**      | The same page, narrowed by the shell, never a second design: the shell and each page kind in `pages.md` (On a narrow screen), what a row of controls does in `foundations.md` (Narrow screens). |

## Behaviour

How things answer the pointer, the keyboard and time, rather than how they look. Most of these the library
already does (Base UI underneath), and a row says so; it also says what to keep when the same thing is built by
hand. Each row starts with **when** it applies; none is added where its when is not met.

| Need                       | When, and build it as                                                                                         |
| -------------------------- | ------------------------------------------------------------------------------------------------------------- |
| **Submenu reached diagonally (safe triangle)** | **Whenever something opens on hover beside what opened it** (a submenu, a hover-opened popover, a flyout from a rail): from the point where the pointer leaves the trigger, a triangle to the near corners of the opened panel, and the strip between the two, keep the panel open, and the rows the triangle crosses take no hover while the pointer is in it. It lets go as soon as the pointer leaves the area, slows below 0.1 px per ms, or rests in it 40 ms short of the panel, so it never holds a panel the reader has given up on. The library's submenus, hover-opened menus and popovers (the info tip) and tooltips have it; a panel opened on hover by hand gets the same, or opens on click instead. A panel opened by click or keyboard needs none: it stays until dismissed. |
| **Hover intent**           | **Whenever hover opens something**, so a pointer passing on its way elsewhere opens nothing: a tooltip opens after 300 ms at rest and closes at once; tooltips along one row (a rail, a toolbar, a row of icon buttons) are grouped, so once one shows, the next opens at once while one is open or within 400 ms of its closing; a submenu opens after 100 ms, since its chevron already says it is there, and closes at 0, the safe triangle doing the forgiving; a hover-opened popover (the info tip) after 300 ms. A close grace of 150 to 300 ms only for a hover-opened panel the reader moves into with no safe triangle to carry them (one not beside its trigger). Never a delay on click, focus or a shortcut: those open at once. Touch has no hover: what hover opens also opens on tap (the info tip), or only names what a tap already does (a tooltip on an icon button). |
| **Focus kept in a dialog, returned on close** | **For every surface that takes over the keyboard** (dialog, sheet, an open menu or popover): on opening, focus moves to the first control inside (the panel itself when opened by touch, so no keyboard springs up); Tab and Shift+Tab cycle inside; Escape closes; on closing, focus returns to what opened it. The library's dialog, sheet, menu and popover do all of this. Two cases change it: when the opener is gone (the row just deleted), focus goes to the row that took its place, or the list's first row, never the top of the page; a tip that only explains (the info tip) leaves focus where it was. |
| **Scroll position kept**   | **When the reader opens an item from a long list and comes back** (an index to a detail page, then Back): the list returns at the scroll position it was left at, the opened row in view and focused; a list reached afresh (from the sidebar, or under other filters) starts at the top. A list whose item opens beside it (a sheet) never moves. |
| **Optimistic update with Undo** | **When an action is reversible and almost always succeeds** (archive, move, mark as read, delete to a bin): the change shows at once, as though done, and a toast says what happened with Undo for its 5 s; Undo puts the thing back exactly where it was, in its place in the list. The request goes as the change shows, and Undo sends its reverse; if the request fails, the thing comes back and an `error` toast says so. An action that cannot be reversed is confirmed first (Destructive action) rather than undone after; one that takes long is a run with progress. |
| **Typeahead in a list**    | **When a list of named options has keyboard focus** (a menu, a select's options): a letter moves to the next option starting with it; letters typed within 750 ms of each other spell one prefix ("ma" finds "Maya"). The library's menu and select do this. A list the reader narrows by typing (a combobox, the command menu, a long menu with its search) filters instead; the sidebar and a table take neither, the command menu and the table's search do that work. |
| **Press and hold to confirm** | **When a destructive action is repeated in place and a dialog each time would be clicked through** (removing members one by one, cancelling queued runs): a hold button: its label says to hold ("Hold to remove"), holding fills it from the start edge over 1000 ms in the error tone and the action runs when it is full; letting go sooner drains it back in 200 ms and nothing happens. Space or Enter held does the same from the keyboard. A rare, grave action (deleting a workspace) keeps the confirmation dialog; one that can be undone needs neither (Optimistic update with Undo). |
