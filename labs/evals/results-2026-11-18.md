# Eval results, 2026-11-18

The first full run of `test-plan.md`: 183 runs over Haiku 5.5, Sonnet 5.5 and Opus 5.5 (about $61), then 22
targeted reruns after fixing the skill and the MCP audit. Runs, screenshots and scores are in
`../continuum-evals/runs/` beside the repo (2026-11-18, -rerun, -grouping); Joan's ratings in `ratings.json` there (looks like
Continuum, 1–5) and `compare.json` (better screen with the look set aside, no Continuum vs the full kit).

## Audit and improve

- Every model finds planted mistakes even without the skill or MCP: the installed package's source and README
  carry the system. Fixes were the weak point (nearest step instead of the role, hedged options).
- The MCP audit missed classes on library components, arbitrary colours and all structure; models copied its
  fixes. After the engine fixes: B1 11/11 with the right fix, B3 5/6, the clean screen reports clean.
- After the skill's review rules, false positives on the clean screen fell (Opus 4 → 0, Haiku with the skill
  7 → 3); the rest are a page-head gap one step off, now ruled within the formula.

## Building

- Joan's ratings of the look: Opus 3.6 · Sonnet 3.5 · Haiku 2.9. Skill alone, MCP alone and the brief alone
  rate as high as skill and MCP together on the same screens.
- Quality with the look set aside (−2 to +2, positive favours Continuum): overall +0.3. Music player +1.3, mail
  client +1.0, orders and notifications +0.7, landing page 0, **photo editor −2 for every model**: Continuum's
  floating panels break an app whose canvas is the work.
- Notes that recur: two text buttons in the floating dock; too much spacing (block gaps, improve runs);
  settings lose hierarchy and scannability; the toolbar needs a hairline above the applied-filter chips; plain
  HTML builds miss the Geist font; app-like screens (player, editor, mail) get the page shell's 96 top offset
  and floating cards.

## Loading the skill

Plan-only prompts suppress loading, so that test measured little; in builds the skill loads when the project
imports `continuum`, and never when the project has only `app.css` and `DESIGN.md`.

## Cheaper models with Continuum against Opus alone (the fair test)

Both sides at the same density: the Continuum builds (rebuilt with the corrected skill and table) re-shot in the
compact, small theme; judged by Joan on composition with the look set aside (`2026-11-18-v2/compare-cheap-small.json`).

| Matchup                               | Won | Lost | Mean (−2…+2) | Cost per screen      |
| ------------------------------------- | --- | ---- | ------------ | -------------------- |
| Sonnet with Continuum vs Opus alone   | 4   | 2    | +0.5         | $0.38 against $0.60  |
| Haiku with Continuum vs Opus alone    | 3   | 3    | −0.2         | $0.065 against $0.60 |

On the tool screens (orders, notifications) both won all four. The losses: the photo editor (both), the music
player and mail client (Haiku), the landing page (Sonnet). The earlier with-against-without comparison mixed the
look with the composition (the Continuum side was drawn in the roomy default theme), so its numbers are not used.

## Final audit (12 runs, skill and MCP, after the fixes)

96/102 planted mistakes found (94%), 94/102 with the right fix (92%); Opus 33/34, Sonnet 32/34, Haiku 31/34; no
false alarms on the correct screen from Sonnet or Opus, 4 from Haiku (one of them the new settings rule applied
where it does not belong). From $0.01 an audit (Haiku) to $0.40 (Opus).

## Found along the way

- A table row with a row menu grew to 50: the skill named the 34 icon button for a row's ellipsis and the cell
  did not take a button in. Now the ellipsis is `icon-sm` and a table cell holds it within the row's 41.
- Settings: the grouping step, and two layouts (ruled, boxed) chosen by what a group holds.
